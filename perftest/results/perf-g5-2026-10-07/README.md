No function body, field, layout, lifecycle operation, or memory order changes.

`investigation/build.py LABEL COMPILER OPTIMIZATION` reproduces builds from

compiler versions, exact commands, and sizes. LDC uses `-O2/-O3 -release`;
DMD uses `-O -inline -release`. Both use the real mimalloc 3.5.3 archive.

| Build | Text bytes | Change from compiler base |

| DMD base and candidate | 1,826,862 | 0 |

Base LDC -O2 calls `ActorOwner!State.requestRetire` and `reclaimActor`
from `actor_churn.main.runCycle`. In targeted -O2, `requestRetire` and
`reclaimActor` are no longer called from `runCycle`: retirement is inlined,
while `reclaimActor` folded into the `ActorOwner!State.reclaim` wrapper,
which -O2 still calls out of line. `ActorHandle.wake` also stays out of line.
Global -O3 inlines both the reclaim wrapper and wake; targeted -O2 therefore
does not reproduce all of -O3's public-loop inlining. The reclaim wrapper and
`ActorHandle.wake` are possible follow-up targets. `driveActorRetirement`
remains out of line. See the saved `*-callers.txt` generated by
`investigation/calls.py`, which includes reclaim and wake calls. The loop
grows from 4,546 to 4,739 bytes.

DMD inlines the owner wrapper but calls the retirement/reclaim helpers.
DMD cannot inline `reclaimActor`, so with `-wi -inline` it prints:

```text
actors/actor.d(1143): Warning: cannot inline function `actors.actor.reclaimActor`
```

It still exits 0, following the existing forced-inline practice in `antfarm.d:2383`
(`enterPayload`). No Makefile uses `-w`, which would promote warnings to
errors. DMD release output remains byte-identical between base and candidate.
