# MT excision investigation — Ryzen 5900XT, October 20, 2026

Two independent regressions were isolated in `fd6271f`, the commit following the MT excision. The ST admission scanner was generalized unnecessarily, and shrinking the table header changed quota truncation, which progressively permuted private-root entry traversal. The final working-tree changes use the hybrid specialized scanner and preserve the unaccepted root suffix at the front of its FIFO. The physical header remains five words. The earlier measurements below document the investigation before those follow-up changes.

## Comparison and method

The October 20 remote `PERFORMANCE.md` uses WSL2; the older 12700H tables used native Windows. Those tables cannot establish the runtime regression or quantify the OS contribution. All comparisons below instead use one native Linux host, compiler, allocator, and explicit CPU placements. They do not measure WSL overhead.

| Label | Revision | Meaning |
| --- | --- | --- |
| pre | `207cd94` | Last revision before MT removal; Farm core unchanged from the 1.8.3 branch |
| excision | `8cc8044` | MT removal, specialized ST scanners still present |
| collapse | `fd6271f` | Five-word header, body-only C callbacks, generalized scanner |
| current | `743935c` | Fetched `origin/1.9.0-progress`; Farm core unchanged since `5a9af40` |
| restored | current + local patch | Restore three ST admission scans; retain 1.9 metadata, ABI and synchronization |

AMD Ryzen 9 5900XT, native Linux 7.2.9-2-cachyos, LDC 1.43.0 / LLVM 22.1.8, `-O2 -release -g`, ordinary pages. `perf stat` collects user cycles, instructions, branches, branch misses and the generic cache-misses event. Five rotating/interleaved process samples per cell; measurements run serially. Medians and ratios of medians below are descriptive, with no background-load rejection or formal performance-gate claim. All raw samples, including outliers, are retained.

The raw probe derives from each revision’s `throughput.d`; differences across revisions are the API migration and singleton-size check. Identical diagnostic additions pin each worker and allow alternating 16/15-word bodies to force indexed uniform tables. Producers occupy CPUs 0 through P−1 and consumers P through P+C−1, without SMT siblings. The first exploratory `screen` batch instead pinned its producer to 1 and consumers to 3 onward; it is not mixed into the patch comparison. CPUs 0–7 share one L3, 8–15 the other; the 4-producer/8-consumer case intentionally spans both.

## Lost specialized admission loops

`fd6271f` replaced the separate uniform-fixed, uniform-indexed and compact scans with one incremental scan. Even when a common callback is known, each body carries candidate layout state and recomputes index/record overhead. The known-length overload, `write(callback, bodies, bodyWords, ...)`, retains its arithmetic admission path. This distinction explains why testing only one overload misses the regression.

The patch restores the ST-only loops from `8cc8044`, adapting them to the current callback API. A loop changes only when a prefix loses uniformity. A non-fitting transition keeps the accepted prefix’s previous layout. Callback validation, overflow checks, quota refresh, the payload cap, preparation, raw stores, and publication/completion ordering remain in place. No MT scheduler or payload header returns.

The restored profile still spends most time in publication/copying; sampling percentages alone are not used as throughput measurements.

The explicit-length control measured 230.343 → 238.175 Mpps, with essentially unchanged retired instructions. That path was not edited; its modest timing shift is not evidence of scanner work being removed from it.

## Independent serial private-root loss

Identical `actor_churn.d` on every revision (SHA-256 `449349ba319f7db36417cf0913ae8b8a4d249c97257b55099b5a52f4aed2ad7a`), the same mimalloc 3.5.3 archive, 16,384 actors, one-second runs, batch 256, five warmups, no consumer threads, controller CPU 2, 16,384-word quota, automatic root hint. Rates are millions of actor lifecycles/sec, including creation, execution, reclamation and verification.

| Mode | pre | excision | collapse | current | current/pre |
| --- | ---: | ---: | ---: | ---: | ---: |
| private | 82.636 | 81.880 | 65.436 | 65.756 | -20.4% |
| private-remote | 80.831 | 80.811 | 66.792 | 66.492 | -17.7% |
| dtor | 82.534 | 81.218 | 65.739 | 65.878 | -20.2% |

These roots use the explicit-length writer, so the scanner restoration does not address their regression. For `private`, pre/current counters are approximately 57.0/71.8 cycles and 200.9/198.2 instructions per lifecycle. Generic cache misses rise from 1.01 to 2.66. The work gets slower despite slightly fewer instructions.

| Three reserved words added to header | 81.264 | 57.85 | 198.24 | 1.18 |
| Callback scope disabled (diagnostic only) | 66.387 | 71.22 | 197.74 | 2.98 |

A stronger control selects five or eight header words at process startup **in the same executable**, retaining the callback guard. Five alternating pairs give:

| Header words | Mlifecycles/sec | Cycles/lifecycle | Instructions/lifecycle | Generic cache misses/lifecycle |
| --- | ---: | ---: | ---: | ---: |
| 5 | 66.056 | 71.61 | 198.38 | 2.75 |

This attributes the recovery to table geometry rather than different generated instructions or the callback guard. A full 256-entry, one-word, one-shard table occupies 293 words with the current header and 296 with the old spacing. Geometry also changes quota packing and possible accepted prefixes; these experiments do **not** distinguish cache alignment/indexing from admission-driven ordering effects. The generic cache event does not identify a particular cache level.

`perf annotate` locates the largest private-root hotspot at the ready-list pointer chase in `pumpRoots`: `ready_ = entry.next`. In the current profile that function receives 29.79% of samples; with the padded header, 13.08%. Samples concentrate on the instruction following the dependent load. Sampling skid prevents treating that individual instruction as an exact stall attribution. This is a useful memory-behavior lead, not proof that padding directly accelerates that store.

Padding additionally raised the raw fixed-width headline from 1,159.172 to 1,216.737 Mpps, while indexed and compact cases were approximately flat. It remains an experimental control, not an adopted wire-format change or a generally established optimization. No spacing change or disabled guard is present in the working-tree patch.

## Comparison with the supplied parallel-session patch

The user supplied a second three-phase scanner as a diff. It was applied exactly to an isolated `current` worktree (`.build/mt-perf/parallel/`). Both candidates use the same diagnostic probe source and build flags. The linked Claude artifact contents were inaccessible, so this comparison covers the pasted diff only. The subsequently tested hybrid is described below.

Both patches restore the same monotonically degrading scan: uniform fixed, then uniform indexed, then compact. Both retain the accepted prefix's layout when a degrading entry would make the table exceed the available quota. The parallel patch improves the fixed phase by validating the first callback and singleton size once, then checking only callback/length equality for subsequent entries. Equality to the validated callback proves non-nullness; equality to the checked length proves the same singleton fits the immutable tier quota. A mismatching entry is reprocessed and validated by the next phase. Zero-length bodies enter the indexed phase directly. No correctness blocker was found.

The parallel patch also uses one payload counter instead of `i` plus `n`, explicitly hoists each phase's header overhead, assigns fixed-phase `psum` after the loop, and statically excludes the compact phase for a common-callback range. The restoration is a more conservative port of the previous specialized loops. Some source simplifications may already be performed by the optimizer; source-level differences alone are not the performance evidence.

The compact phases differ: the restoration keeps a running compact-record sum, whereas the parallel patch keeps the body sum and computes checked `nextBody + nextN` for every candidate. The latter generated more retired instructions and branches in these workloads. The indexed phase also measured slightly more instructions. These are whole-process counters, not exact per-loop instruction counts.

## Table spacing: quota truncation permutes the root queue

The decisive control keeps the same executable and changes only header words and quota. With a one-word body and one shard, a full batch of 256 occupies 293 words with the five-word header and 296 with eight words. At the default 16,384-word quota, the first grant admits 55 full tables, then 232 roots with five header words or 64 with eight.

`pumpRoots` detached up to 256 entries before calling `write`, then appended an unaccepted suffix to the back of the ready queue. Completed roots return to a LIFO free list. On the next lifecycle, spawning traverses that free list. Repeated partial admissions therefore permute both lists. Header size changes the partial-prefix pattern and thus the resulting physical entry traversal, even when callback and allocator work are identical.

Five interleaved process samples per cell, the original runtime-selectable-header executable, 16,384 roots, batch 256, no consumer threads:

| Header words | Quota words | Quota choice | Mlifecycles/sec | Instructions/lifecycle | Generic cache misses/lifecycle |
| --- | ---: | --- | ---: | ---: | ---: |
| 5 | 16,384 | Default | 66.043 | 198.38 | 2.760 |
| 8 | 16,384 | Default | 81.770 | 198.39 | 1.310 |
| 5 | 16,408 | 56 whole tables | 85.965 | 198.18 | 0.225 |
| 8 | 16,576 | 56 whole tables | 85.873 | 198.18 | 0.222 |
| 5 | 4,688 | 16 whole tables | 86.537 | 198.19 | 0.233 |
| 8 | 4,736 | 16 whole tables | 86.401 | 198.19 | 0.222 |
| 5 | 16,216 | First partial prefix is 64 roots | 81.685 | 198.39 | 1.337 |

Whole-table grants eliminate the large gap without restoring the physical header size. The five-word header can also recover the eight-word default result by changing only its quota. An additional eight-word/16,552-quota cell measured 71.951 Mlifecycles/sec, with substantial variation: matching the first partial prefix alone does not guarantee matching admission sequences across later lifecycle boundaries.

A separate instrumented build records entry-index distances while `pumpRoots` walks its ready list. These runs are used for topology evidence, not throughput:

| Header / suffix placement | Adjacent entry steps at lifecycle 5,000 | Mean absolute entry-index step |
| --- | ---: | ---: |
| 5 / back | 9,435 of 16,468 (57.3%) | 2,303.1 |
| 8 / back | 16,191 of 16,447 (98.4%) | 91.1 |
| 5 / front | 16,467 of 16,468 (>99.99%) | 1.005 |

At lifecycle 1,000, the corresponding adjacent fractions are approximately 89.1%, 98.4%, and >99.99%. The five-word/default/back case progressively loses locality. The entry array is 40 bytes per slot, or 640 KiB for this workload; this host reports a 512 KiB private L2. The generic cache-misses counter does not identify the cache level, so no particular cache-level stall is asserted.

The causal control retains the five/eight-word selector and adds a runtime switch for placing only the unaccepted suffix back at the front. Seven interleaved samples per cell, each doing exactly 5,000 measured lifecycle rounds plus five warmups, use the same non-instrumented executable:

| Header words | Suffix placement | Mlifecycles/sec | Cycles/lifecycle | Instructions/lifecycle | Generic cache misses/lifecycle |
| --- | --- | ---: | ---: | ---: | ---: |
| 5 | Back | 64.722 | 73.17 | 197.37 | 2.304 |
| 5 | Front | 87.257 | 53.69 | 197.36 | 0.237 |
| 8 | Back | 82.702 | 56.80 | 197.41 | 1.297 |
| 8 | Front | 86.915 | 53.91 | 197.38 | 0.245 |

This removes the regression through queue order while retaining the smaller table format. Instruction counts barely change; pointer locality and cache-miss behavior improve. Together with the whole-table quota controls and direct traversal trace, this identifies admission-driven entry permutation as the main cause in this serial workload. It does not establish that physical alignment never matters in other workloads.

## Final candidate and original actor benchmark

The final candidate combines the hybrid scanner with a small `pumpRoots` change. When `n < count`, the unaccepted suffix is reattached at the front using its existing links. Only the last unaccepted entry's link and the ready head/tail are changed. The accepted prefix is not dereferenced; all-published batches skip this work. Completion custody, memory orders, allocator policy, and the five-word table format remain unchanged.

Five interleaved samples on the original, byte-identical `actor_churn.d`, with no geometry switches or tracing, use the same mimalloc archive and original one-second protocol:

| Mode | Pre-excision Mlifecycles/sec | Current | Hybrid + queue fix |
| --- | ---: | ---: | ---: |
| private | 82.124 | 65.638 | 84.968 |
| private-remote | 79.835 | 66.138 | 86.554 |

For private roots, instructions/lifecycle are 198.23 → 198.18 and generic cache misses/lifecycle 2.644 → 0.215. These figures measure the final candidate on remote base `743935c`; the same edits are applied locally without rebasing unrelated working-branch changes.
